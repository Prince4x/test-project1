## 1. TL;DR — your repo is not a "basic Teen Patti game"

The prompt says "I built a basic Teen Patti game". What is actually in `Prince4x/test-project1`

- a hand-rolled WebSocket server, room manager, chat, leaderboard, reconnect-by-profile,
- 4 AI personalities with Monte-Carlo equity, side shows, all-in side pots, turn clocks,
- a polished casino lobby + felt table view with deal/flip/chip animations and a

So the honest plan is **not** "build Phase 1 from scratch". It is:

1. **Close the real rule gaps** between your spec and what the engine does today,
2. **Add the one missing architectural piece** your roadmap requires — *one rules engine
   driven by a mode-config object* (today there is no mode concept at all),
3. Then spend the saved effort on the things that genuinely are missing: variants,
   progression, tournaments, drama/polish.

**Architecture worth preserving** (it is better than most of what I'd write fresh):

- The engine **never touches timers or I/O**: `config.clock` is injected, hosts call
  `checkTimeout(now)`. That is why timer tests are deterministic.

  this property** (a Joker/Muflis table must not leak which wilds a player is holding).
- Practice mode and the server run **the same file**, so there is no rules drift.

## 4. Rule deltas: your spec vs. the engine today

These are the items I will **not guess about** — they are the questions in §8.

| # | Rule | Your spec | Engine today | Impact |
| --- | --- | --- | --- | --- |
| A | **A-2-3 ordering** | `A-K-Q` > `A-2-3` > `K-Q-J` … | `A-K-Q` > `K-Q-J` … > `A-2-3` (**lowest** run) | Verified: `compareHands(['AS','3S','2S'], ['KH','QH','JH']) === -1` |

## 5. Refactor needed *before* variants (Phase 2)

Adding Joker/Muflis/AK47/1942 naively would duplicate rules in four places (engine, AI,
UI, server). Your "one engine, one config" requirement means doing this first:

1. **`src/engine/modes.js` (new, ~120 lines)** — the single source of truth for modes.
   Each mode is a plain object: `{ id, name, blurb, howToPlay, wilds: {ranks:[], cards:[],
   joker:{mode:'rank'|'printed', count}}, ranking: 'high'|'low', sequenceAceLow: 'lowest'|'second',
   boot, turnSeconds, maxRounds, potLimit, chaalLimit, sideshow, tieRules, … }`.
   `Classic` is simply the default config; `Fast` is Classic with different numbers;
   `Hukam` slots in later with zero engine changes.
2. **`evaluator.js`** — `evaluate(cards, options)` where `options` is the mode's ranking
   slice. Three additions:
   - **wild substitution**: enumerate candidate replacements and keep the best hand
     (the *lowest* in Muflis). Naive brute force is 52³ ≈ 141 k evaluations — too slow
     for the AI's Monte-Carlo. Reduced candidate set (all 13 ranks × {suits already in
     the hand} ∪ {one representative off-suit}) keeps the worst case ≈ 2–3 k, plus a
     `Map` memo cache keyed by `mode|sorted cards` → fast enough for 36-trial equity.
   - **lowball**: keep the normal key and flip the comparator (`compareHands` returns
     `-normal`) so categories *and* tie-breaks reverse consistently; `handStrength` is
     mirrored so bots still "want" the best Muflis hand.
   - **configurable A-2-3** (question A).
3. **`table.js`** — accept `mode` (id or object) in `DEFAULT_CONFIG`, expose it in
   `serialize()`, reveal the Joker card via a new `hand:start` event payload field, and
   honour `potLimit` / `chaalLimit` / `maxBlindRounds` / tie rules (questions B–F).
4. **`ai.js`** — pass the mode into `estimateWinRate` / `decideAction`; wild hands change
   equity, so the Monte-Carlo must evaluate with the same mode.
5. **`server/rooms.js` + `index.js`** — accept a **mode id from an allowlist** (never raw
   config from a client), publish it in `/api/config` and table info.
6. **`tools/build-standalone.mjs`** — register any new engine module in `MODULES`
   (it is a hand-written bundler; a new file is silently missing from the offline build
   otherwise). `test/standalone.test.js` guards that.
7. **`cards.js`** — `createSecureRng()` using `crypto.getRandomValues` (Node ≥ 19 has
   `globalThis.crypto`; browsers have had it forever), used **by default**; the seeded
   PRNG stays for tests, replays and `/api/replay/:seed`.

## 8. Questions — and the answers you gave (2026-09-25)

1. **A-2-3 ordering** — lowest run (today) or second-highest (`A-K-Q > A-2-3 > K-Q-J`,
   your spec), and should Classic default to that with a per-table switch?
2. **Per-turn bet cap** — keep today's uncapped raises, or enforce your
   blind ≤ 2x / seen ≤ 4x ceiling on Classic tables?
3. **Side show** — charge the min chaal and require the target to be *already seen*
   (your spec), or keep it free with a blind target force-looked (today)?
4. **Show ties** — requested show → requester loses, forced show → split (your spec), or
   always split (today)?
5. **Phase 1 scope** — given the audit: (a) rules conformance + secure shuffle + showdown
   drama *(my recommendation)*, (b) pure UI/feel polish only, or (c) skip ahead to the
   mode engine and variants?

**Decisions:**

| # | Question | Decision |
| --- | --- | --- |
| 1 | A-2-3 ordering | **Configurable, default = the spec.** `A-K-Q > A-2-3 > K-Q-J` in Classic; `sequenceAceLow: 'lowest'` restores the old ordering. |
| 2 | Per-turn bet cap | **Enforced on Classic.** `maxBetMultiple: 2` — a raise may at most double the stake (blind ≤ 2x, seen ≤ 4x in the half-rate notation). |
| 3 | Side show | **Charge the minimum chaal, keep the force-look.** Asking costs your minimum chaal and *is* your bet for the round; a blind player who is asked is still made to look (`sideShowTargetMustBeSeen: false`). |
| 4 | Show ties | **Configurable, default = the spec.** `showTie: 'requester-loses'`, `forcedShowTie: 'split'`. |
| 5 | Phase 1 scope | **Rules conformance + secure shuffle + showdown drama** (the recommended option). |

One consequence worth knowing: because a blind raise must already double the stake *and*
the new cap is "the stake may double", a blind player has exactly one legal raise size —
double the stake, for half the price. That falls out of the two rules together, and it is
what the "blind may bet up to 2x" wording describes.
